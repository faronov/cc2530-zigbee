# Открытый Zigbee для CC2530

Экспериментальный проект на **C и SDCC**: сначала End Device с постоянно
включённым приёмником, затем Sleepy End Device. Цель — обойтись без IAR и
закрытых библиотек Zigbee.

**Сейчас здесь стартовая прошивка, инструменты аппаратной отладки с явными
разрешениями, ограниченный пассивный RX и однокадровый TX в отдельных тестовых
образах, офлайн-компоненты протокола, проверки и CI.
Работающего Zigbee-стека пока нет.** Образ `bringup` по умолчанию не включает
радио. Для отдельных образов [TX/RX подтверждены на железе](docs/DEBUGGING.md#2026-09-21-lg-tx-and-passive-rx-demonstration),
но подключения к сети, приложения с датчиком и обновления экрана ещё нет.

## Быстрый старт

Работайте из Git-клона репозитория. Нужны SDCC 4.2.0, `s51`, Python 3.9 или
новее, GNU Make и компилятор C для компьютера.
На Ubuntu 24.04:

```sh
sudo apt-get update
sudo apt-get install --no-install-recommends \
  build-essential python3 sdcc=4.2.0+dfsg-1 sdcc-ucsim=4.2.0+dfsg-1
make BOARD=generic all test
make BOARD=lg_esl29_rev03 all test
python3 -m unittest discover -s tools -p 'test_*.py'
python3 tools/check_repository.py
```

На macOS достаточно добавить установленный SDCC 4.2.0 с `s51` в `PATH`
и выполнить те же команды `make`. Результат находится в `build/<board>/`.
Сборка и GitHub Actions **не прошивают подключённые устройства**.

## M1: тестовая прошивка и аппаратная отладка

Отдельный образ без радио предназначен для проверки CC Debugger:

```sh
make BOARD=generic IMAGE=debug_fixture all test
make BOARD=lg_esl29_rev03 IMAGE=debug_fixture all test
```

Артефакты находятся в `build/<board>/debug_fixture/`. Образ сохраняет
стартовую политику платы и статус M0; добавлены четыре именованные точки
в коде, вложенные вызовы, 16-байтный блок состояния и NOP/RET с известными
значениями регистров. Формат и порядок проверки описаны в
[документации отладчика](docs/DEBUGGING.md#implemented-target-fixture).

Для обеих плат выполнены **host-тесты, проверки связанного образа и симуляция
с учётом алиаса IRAM**. 2026-09-16 неизменённый образ LG размером 626 байт
проверен **на одной физической LG Rev0.3**: четыре breakpoint-слота, 257 циклов
с переполнением счётчика, сохранение регистров, шаг NOP, сброс и повторная
инициализация, алиас RAM, ошибки USB и восстановление после остановки на
границе «flash стёрта, CPU остановлен». Точный образ, адаптер, итоговый прогон
с изолированным PyUSB 1.3.1 и ограничения указаны в
[датированной записи](docs/DEBUGGING.md#2026-09-16-lg-fixture-hardware-record).
Плата generic аппаратно не проверена; отдельные образы `bringup` не прошивались.
В рамках M1 общий startup проверялся на железе только в составе LG fixture;
последующая аппаратная проверка timebase описана отдельно ниже.

[Host-транспорт](docs/DEBUGGING.md#implemented-host-transport) поддерживает
явный выбор USB bus/address, status/config, PC/банк/регистры, ограниченные
чтения SFR/XDATA/CODE, запись SRAM с проверкой и аппаратные breakpoints
для небанкированного CODE. Для чтения PC/регистров/памяти CPU должен быть
остановлен и находиться в нормальном активном состоянии. Управление CPU,
сброс, доступ к памяти, запись памяти и breakpoints разрешаются отдельно.
Публичная запись ограничена XDATA `0x0000..0x1DFF`: статус, алиас IRAM,
MMIO и flash недоступны для записи. Восстановление регистров выполняется
и проверяется только после успешных обменов. При ошибке сессия переходит
в `FAULTED`, без повторов, автоматического восстановления, запуска CPU
или очистки stall.

Первичный разрушительный `attach-reset` требует отдельного подтверждения;
`reset-halt` работает только в уже подготовленной сессии. Это не подключение
без сброса. Открытие и закрытие сессии не сбрасывают и не запускают CPU.
[Ручной прогон и инструмент восстановления](docs/DEBUGGING.md#manual-hardware-acceptance-and-recovery)
не запускаются сборкой или CI. PyUSB не нужен для обычных тестов:
они используют синтетические бэкенды и никогда не перечисляют USB-устройства.

[Офлайн-инструмент](docs/DEBUGGING.md#offline-image-symbol-and-snapshot-tools)
ищет глобальные символы и точные соответствия адресов строкам CDB,
разбирает статусы M0/M1 и подготавливает параметры
breakpoint по проверенным образам и хешам, **не обращаясь к USB**.
Ближайшая строка не угадывается; пути к исходникам не открываются.

**M1 завершён для ограниченной конфигурации LG с небанкированным CODE.**
После первого подтверждённого подключения кабеля полная проверка fixture
прошла успешно. Последующее финальное отключение с открытым сеансом
CC Debugger подтвердило `FAULTED`, запрет resume без нового I/O и явную
ошибку очистки. После последнего подключения PyUSB снова обнаружил адаптер;
после явного выбора адаптера в новом сеансе полная одноцикловая проверка
fixture также прошла успешно. Этот последний запуск оставил fixture
остановленной на `0x0173`.
Различение банков потребуется при появлении банкированного CODE.
Завершение этого этапа не означает аппаратную проверку generic, поддержку
спящих целей, MMIO/всех SFR, записи flash, GDB, M2, радио или сети.

## Первый срез M2: счётчик времени без сна

Отдельный [модуль времени](docs/ARCHITECTURE.md#awake-only-timebase-first-m2-slice)
читает 24-битный Sleep Timer в порядке ST0/ST1/ST2 с аппаратной фиксацией
значения и вычисляет ограниченные модульные дедлайны. Некорректные аргументы
и неоднозначная разность ровно в половину диапазона возвращают явную ошибку
без изменения результата. Допустим один владелец чтения в основном потоке;
выбор часов, миллисекунды, прерывания, compare и пробуждение не реализованы.
`make test-timebase` выполняет **host-тесты, проверку связанного образа и
симуляцию с алиасом IRAM**, но не подтверждает физический ход или точность
счётчика. Отдельно через M1-отладчик на LG наблюдались ход счётчика и
естественное переполнение; это не запуск нового C-драйвера и не калибровка
времени. [Границы аппаратного наблюдения](docs/VALIDATION.md#independent-sleep-timer-hardware-reference-2026-09-16)
зафиксированы отдельно. Самостоятельный тестовый образ нельзя прошивать;
модуль по-прежнему не включён в `bringup` и `debug_fixture`, их байты и
аппаратные свидетельства M1 не изменены.

Следующий отдельный срез добавляет
[тестовую прошивку времени для платы](docs/DEBUGGING.md#awake-only-timebase-board-fixture):

```sh
make BOARD=generic IMAGE=timebase_fixture all test
make BOARD=lg_esl29_rev03 IMAGE=timebase_fixture all test
```

Образ `timebase_fixture` вызывает настоящий C-драйвер с задержкой 128 сырых
тиков и независимым пределом 1024 опроса. Ошибка фиксируется без автоматического
повтора; startup, GPIO-политика и статус M0 сохранены. Результаты находятся в
`build/<board>/timebase_fixture/`. Для обеих плат выполнены **host-тесты,
проверки связанного образа и симуляция**. 2026-09-16 проверенный LG-образ
размером 1847 байт также прошёл
[аппаратную проверку с выполнением C-драйвера](docs/DEBUGGING.md#2026-09-16-lg-compiled-c-timebase-acceptance):
257 циклов, 129..130 сырых тиков при запросе 128, ровно 37 опросов на цикл,
переполнение байтовых счётчиков и сохранение CPU/статуса M0. Тот запуск
оставил timebase-образ в READY на `0x016A`; последующая проверка часов описана
отдельно ниже. Ручной runner не прошивает устройство и независимо
проверяет весь физический CODE перед запуском.

Плата generic и физические испытания отказов таймера остаются аппаратно
непроверенными. Ветви остановленного, обратного и неоднозначного хода счётчика
проверены только host-тестами и симуляцией. Этот C-прогон не подтверждает
калибровку или естественное 24-битное переполнение таймера. CI охватывает обе
платы и пять видов образов; самостоятельные тестовые исполняемые файлы не
загружаются как артефакты прошивок. **M2 #4 остаётся открытым**: измерение/калибровка
часов, IRQ/compare/пробуждение и остальные платформенные критерии не закрыты.

Следующий изолированный [драйвер системных часов при инициализации](docs/ARCHITECTURE.md#init-time-system-clock-selector-isolated-m2-slice)
запрашивает RC16/XOSC32 через настоящие CMD/STA, с ограничением по сырым тикам
и числу опросов. При ошибке выполняется одна ограниченная проверка возврата
к исходным настройкам; исходная ошибка не превращается в успех.
`make test-clock` даёт только **host-тесты, проверку связанного образа и
симуляцию с алиасом IRAM**. Отдельная ограниченная аппаратная проверка C-кода
на LG описана ниже.
Драйвер не включён ни в один из шести прежних образов плат; их BIN не изменены.
Самостоятельный `clock_test.ihx` нельзя прошивать или публиковать как образ
платы. Выбор LF-источника, сервис калибровки и поддержка сна/IRQ не добавлены.

Следующий отдельный [образ для проверки часов](docs/DEBUGGING.md#init-time-clock-board-fixture)
собирается как `IMAGE=clock_fixture` для обеих плат и вызывает настоящий драйвер:
RC16 без переключения, XOSC32, возврат RC16. Результаты сериализуются в 56 байт;
ошибка фиксируется без повтора и без превращения успешного rollback в успех
исходного запроса. Ручной runner требует отдельного разрешения и сверяет весь
физический CODE до запуска. Отрицательный тест останавливается в строго
проверенном RET расчёта дедлайна перед запросом часов, без инъекции RAM/ROM.
[Первый LG-эксперимент](docs/DEBUGGING.md#2026-09-16-lg-clock-cancellation-failure)
подтвердил обычную последовательность `C9 -> 88 -> C9`, но **проверка rollback провалилась**:
старое STA временно совпало, после чего проявился отложенный переход на XOSC.
Исправление требует наблюдать запрошенный источник, затем возврат; если
переход не наблюдался до исчерпания границ, результат —
`CLOCK_ROLLBACK_UNCONFIRMED=9`, не успех.

Исправленный LG-образ размером 3798 байт прошёл
[аппаратную проверку с выполнением C-кода 2026-09-17 (UTC+03)](docs/DEBUGGING.md#2026-09-17-lg-compiled-c-clock-acceptance).
Исходный тест отмены ожидающего запроса прошёл без ослабления: возврат
подтверждён лишь через 64 сырых тика / 15 опросов. Отдельный тест позднего
тайм-аута также прошёл; оба сохранили исходный TIMEOUT и терминальный FAULT.
Затем отдельный явный reset/recovery-прогон выполнил 257 полных
последовательностей (771 настоящий C-вызов), включая переполнения счётчика/
heartbeat и сохранение CPU/M0/полей часов. Тот прогон оставил clock-образ
на LG в READY `0x016A`, источник RC16; последующая проверка IRQ ниже
изменила установленный образ.
Generic остаётся **host/image/симуляцией**, без аппаратного результата.
Это не измерение частоты/калибровка, физический отказ генератора/остановка
таймера или подтверждение отмены без наблюдавшегося перехода. Исторические
свидетельства M1/timebase сохранены. M2 остаётся открытым.

## M2: основа владения прерываниями

Изолированные [примитивы EA](docs/ARCHITECTURE.md#interrupt-ownership-foundation-isolated-m2-slice)
сохраняют прежнее глобальное разрешение прерываний, атомарно выключают его
и восстанавливают ровно сохранённый байтовый токен 0/1. Вложенность требует
LIFO; внутренний выход не включает прерывания внешней секции. Токены 2..255
отклоняются без доступа к регистрам прерываний/периферии. Подделку корректного
0/1, повторное использование и нарушение порядка API обнаружить не может.

`make test-irq` выполняет **host-тесты, проверку связанного образа и симуляцию
с алиасом IRAM**, включая настоящий вход в обработчики generic C52,
вложение по старшему приоритету и сохранение контекста при RETI.
Реентерабельные SDCC-примитивы не являются диспетчером периферии или
аппаратной проверкой прерываний CC2530. Восемь прежних BIN сохранены;
следующий отдельный IRQ-образ намеренно включает эти примитивы. Самостоятельный `irq_test.ihx`
**нельзя прошивать или публиковать как образ платы**. Эта синтетическая
проверка отделена от ограниченного аппаратного результата LG ниже; M2 #4
остаётся открытым.

Отдельный `IMAGE=irq_fixture` собирается для обеих плат и проверяет настоящий
C-код на одном источнике Timer1: переполнение при EA=0, вложенное сохранение/
восстановление, ожидающее событие после внутреннего restore(0), затем ISR/RETI
и следующий независимый запуск. Счётчик останавливается до включения EA,
обработчик маскирует свой источник перед подтверждением. Выводов таймера,
общего диспетчера, DMA, сна или радио нет.
[Ручной runner и ABI](docs/DEBUGGING.md#timer1-irq-board-fixture) требуют отдельного
разрешения и сверяют весь физический CODE до запуска CPU через runner.
Неизменённый LG-образ размером 3269 байт прошёл
[аппаратную проверку C-кода Timer1/IRQ 2026-09-17 (UTC+03)](docs/DEBUGGING.md#2026-09-17-lg-compiled-c-irq-acceptance):
три начальных цикла, отдельный TIMEOUT с сохранением FAULT, затем отдельный
reset/recovery-прогон из 257 циклов и настоящих ISR с переполнениями байтовых
счётчиков. Возврат каждого нормального прерывания был на `0x0C9D`:
**restore+12, уже с DPL=OK (0)**, а не синтетический restore+9 с токеном 1.
Полный контекст CPU/активной IRAM и шаг настоящего RETI проверены.
Тот прогон оставил IRQ-образ в READY `0x01BB`, с выключенными EA/T1IE и
остановленным Timer1; последующая проверка FIFO описана ниже.
Generic остаётся **host/image/симуляцией**.
Это не калибровка времени/задержки, аппаратный one-shot, точное число
переполнений таймера, вложенность по старшему приоритету или поддержка других
IRQ/DMA/сна/радио/AES/flash. Восемь прежних BIN и исторические записи сохранены;
Этот IRQ-срез добавил десять комбинаций CI с прежним строгим списком артефактов.
Прошлая проверка не разрешает новые действия с железом; M2 #4 остаётся открытым.

## M2: изолированная основа radio FIFO

[API FIFO](docs/ARCHITECTURE.md#quiescent-radio-fifo-foundation) выполняет
проверяемую очистку RX/TX FIFO и ограниченную загрузку TX через настоящие
RFST/RFD. Требуются заранее установленный покой radio/CSP/DMA и стабильный
XOSC32; RF не включается, ошибки контроллера не стираются. Принимаются
1..125 байт тела без PHR/FCS; записываются PHY-длина и тело, с проверкой
счётчика/указателей после каждого байта. Это не передача или проверка MAC.
`make test-radio-fifo` даёт только **host/image/синтетическую FIFO/CSP-симуляцию**.
`radio_fifo_test.ihx` нельзя прошивать или публиковать как образ платы.
Отдельный [`IMAGE=radio_fifo_fixture`](docs/DEBUGGING.md#quiescent-radio-fifo-board-fixture)
теперь выбирает и подтверждает XOSC32, проверяет пустое состояние, малую
XDATA- и максимальную CODE-загрузку, читает только принятые синтетические
байты TX RAM и явно очищает TX между загрузками. Ручной runner не запускается
сборкой или CI. LG-образ размером 8979 байт прошёл
[ограниченную аппаратную проверку 2026-09-17 (UTC+03)](docs/DEBUGGING.md#2026-09-17-lg-compiled-c-fifo-acceptance):
257 циклов после отдельного сброса, 33 410 записанных и проверенных байт,
514 явных очисток TX. Отдельный таймаут сохранил один записанный, но не
подтверждённый байт и терминальный FAULT, без неявного восстановления.
Generic остаётся **host/image/синтетической симуляцией**. Очистка непустого
RX, приём кадров, FCS и работа в эфире не проверены. Тот FIFO-прогон оставил
на LG FIFO-образ в READY `0x016A`, с XOSC32, выключенными IRQ и пустыми FIFO.
Все десять прежних BIN и исторические записи сохранены. M2 #4 открыт.

## Изолированный DMA как отдельная предпосылка

[DMA канала 0 с единственным владельцем](docs/ARCHITECTURE.md#isolated-channel-0-dma-copy)
копирует 1..16 байт между буферами XDATA с ограниченными ожиданиями и
терминальной фиксацией ошибки. `make test-dma` даёт только **host/image/
синтетические DMA-проверки**; `dma_test.ihx` нельзя прошивать.
Этот RAM-only этап не проверяет AES или периферийный DMA;
[пробел в CPU-последовательности AES](docs/PROVENANCE.md#m2-aes-cpu-transfer-prerequisite)
и оставшиеся радиочастотные требования не закрыты.
[Отдельный debug-config API](docs/DEBUGGING.md#guarded-dma-enable-after-reset)
прошёл ограниченную проверку на LG; это не проверка DMA-копирования.

Отдельный [`IMAGE=dma_fixture`](docs/DEBUGGING.md#channel-0-dma-board-fixture)
имеет host/image/симуляционные проверки обеих плат и
[ограниченную аппаратную проверку LG 2026-09-17](docs/DEBUGGING.md#2026-09-17-lg-compiled-c-dma-acceptance):
257 циклов после отдельного сброса, 514 копирований / 6289 проверенных байт
на RC16/XOSC32 в обоих направлениях. Отдельный таймаут сохранил завершение
без ACK и терминальный FAULT, без чтения или повторного использования буферов.
Только эти два образа включают драйвер DMA-копирования RAM; generic остаётся
без аппаратного результата.
Все двенадцать прежних BIN неизменны; на этом этапе CI вырос до четырнадцати комбинаций
с прежним списком семи артефактов и `hardware_tested=false`.
Тот DMA-прогон оставил на LG образ размером 8890 байт в READY `016A`,
с config22, RC16, выключенными IRQ и пустыми ARM/REQ/DMAIRQ.

## Изолированная основа AES-128 через DMA

[`aes128_encrypt_block`](docs/ARCHITECTURE.md#isolated-aes-128-dma-block)
шифрует один 16-байтный блок через два AES-triggered DMA-канала: постоянные
приватные буферы, единый deadline/poll cap и терминальная фиксация ошибки.
`make test-aes` проверяет публичные NIST-векторы, независимый host-only
математический эталон, настоящий SDCC ABI CODE/XDATA и синтетические передачи
по дескрипторам и адресным alias. Эти автоматические проверки дают
**host/image/симуляционные результаты**, отдельно от ограниченных аппаратных
наблюдений LG ниже. `aes_test.ihx` нельзя прошивать; все четырнадцать прежних BIN
и список семи артефактов неизменны. Нет ECB для сообщений,
CCM/аутентификации, управления ключами или программного production fallback.
[Оставшиеся аппаратные AES-проверки](docs/VALIDATION.md#m2-isolated-aes-dma-block-coverage)
и CPU-only последовательность остаются открытыми.

Отдельный [`IMAGE=aes_fixture`](docs/DEBUGGING.md#aes-dma-board-fixture)
имеет host/image/симуляционные проверки обеих плат: настоящий C-драйвер,
21 публичный вектор, все сочетания CODE/XDATA, обе частоты и 257 циклов после
одного сброса; ограниченная аппаратная проверка LG описана ниже.
Ручной инструмент проверяет весь CODE до разрешения DMA и готовит настоящие
pre-key/final timeout, не читая приватные буферы после ошибки. Тот этап расширил
CI до 16 полных заданий с прежними семью артефактами и `hardware_tested=false`.
[Первая аппаратная загрузка KEY на LG](docs/DEBUGGING.md#2026-09-17-first-lg-aes-key-load-failure)
выявила ошибку предположения о флагах. Неизменённый исправленный
**LG-образ размером 12765 байт** затем прошёл
[короткий нормальный прогон, оба точных таймаута и восстановление после сброса](docs/DEBUGGING.md#2026-09-17-corrected-lg-aes-bounded-acceptance).
Normal3 принял шесть блоков на обеих частотах: векторы0/1/2, сочетания памяти0/1
и 18 подтверждённых ENC ACK. Свежие флаги **KEY и IV** и подтверждения каждой фазы
теперь наблюдались аппаратно; оба таймаута сохранили выходной буфер вызывающего.
Отдельное восстановление после нового сброса завершило 257 циклов и 514 принятых
блоков: независимо проверены все 168 сочетаний вектор/память/частота и 1 542
подтверждённых ENC ACK. Тот AES-прогон завершился в
**READY016A/config22/RC16**, completed/heartbeat1, fault latch0; после
последующей прошивки PRNG ниже это историческое состояние.
Generic остаётся без аппаратных AES-наблюдений. Это не калиброванное время,
не общая проверка DMA/безопасности и не закрытие M2 #4.

## Изолированная детерминированная основа PRNG

[`prng_seed_explicit` / `prng_next16`](docs/ARCHITECTURE.md#isolated-deterministic-prng)
предоставляют **аппаратный детерминированный LFSR с явно заданным seed,
не источник энтропии и не криптографический RNG**. Seed загружается старшим
байтом первым; одна ограниченная команда выполняет 13 сдвигов с обратной
связью и возвращает полное 16-битное состояние. Запрещены неподвижные состояния
`0000` и `8003`; полный host-анализ выявляет два остальных цикла по 32 767
состояний, а не период 65 535.

Отдельная [основа проверки бинарного шума](docs/ARCHITECTURE.md#binary-raw-noise-health-test-foundation)
реализует RCT/APT с явными диагностическими порогами и host/image/simulator
проверками. Она не собирает RF-данные и не подтверждает энтропию: даже
периодический сбалансированный поток может пройти эти тесты.
`make test-noise-health` — отдельный офлайн-тестовый образ.

Отдельный [стендовый образ raw IRND с явным допуском](docs/RADIO_NOISE_FIXTURE.md)
`IMAGE=radio_noise_fixture` после сброса находится в DISARMED: нужны точные
команды ARM, затем RUN. Настоящие startup/clock/collector/health выполняют
единственный захват1024 бит на канале26; результат health хранится отдельно.
Обе платы прошли native/ASan/UBSan и genuine linked/alias-aware проверки.
Аппаратная приёмка остаётся открытой; пороги21/589 не подтверждают энтропию.
**Тестовые `radio_noise_test.ihx` и `noise_health_test.ihx` прошивать нельзя.**

`make test-prng` проверяет настоящий драйвер независимыми host-моделями
и отдельным SDCC-исполняемым файлом под alias-aware симулятором.
**`prng_test.ihx` нельзя прошивать.** Отдельный
[`IMAGE=prng_fixture`](docs/DEBUGGING.md#deterministic-prng-board-fixture)
теперь связывает неизменённый драйвер для обеих плат. Пакеты по 32 слова
с настоящим последним пакетом из 31 слова проверяют четыре периода по
32 767 слов: оба непересекающихся цикла на RC16/XOSC32, плюс короткие
seed/reseed-прогоны. Host сравнивает каждое фактическое слово, не только
счётчик или хеш. Отдельно выбираемый RCTRL11-probe проверяет терминальный
отказ; удержание CPU **не** создаёт честный PRNG poll-timeout.
Добавление PRNG сохранило все16 прежних BIN и драйверы.
Добавление пассивного RX расширило CI до20 заданий; офлайн flash fixture
ниже расширила его до22 заданий, TX — до24, raw-IRND board fixture — до26
с прежними семью артефактами и `hardware_tested=false`.
Исходный **LG PRNG-образ wirev1 размером 7224 байта** прошёл
[короткую аппаратную проверку 2026-09-17](docs/DEBUGGING.md#2026-09-17-lg-prng-short-acceptance):
две загрузки seed1234 и восемь слов на RC16, повторивших
`8D94 E5AC CBBE 1731`, с проверками ожидаемых нетерминальных отказов,
чтений без продвижения LFSR, защитных байтов и незаполненного хвоста буфера.
[Первый длинный прогон прервала ошибка проверки флагов fixture](docs/DEBUGGING.md#2026-09-17-lg-prng-long-run-flag-policy-interruption):
Sleep Timer выставил STIF после снимка C при достижении reset-значения compare.
Это не отказ драйвера/выхода PRNG; последний пакет из32 слов host не принял.
Исправленный wirev2 допускает только сохранение STIF и переход0->1, проверяя
порядок C/live-наблюдений; остальные биты остаются строгими, флаги не очищаются.
Неизменённый **LG wirev2 размером 7289 байт** затем прошёл
[короткую аппаратную проверку исправленного образа](docs/DEBUGGING.md#2026-09-17-corrected-lg-prng-short-acceptance):
восемь слов на RC16 и шесть наблюдений флагов **без перехода STIF**.
Тот же образ затем прошёл
[полную аппаратную проверку stopped](docs/DEBUGGING.md#2026-09-17-corrected-lg-prng-full-stopped-acceptance):
131 084 слова проверены по отдельности, четыре периода по32 767 и все65 534
допустимых состояния на каждой частоте. Наблюдались настоящий переход
C0/live80 STIF и2 145 последующих сохранённых наблюдений, а также probe
RCTRL11 с ответами6/6/6 и неизменными данными вызывающего.
Тот же образ прошёл
[отдельное восстановление полным сбросом](docs/DEBUGGING.md#2026-09-17-corrected-lg-prng-full-reset-recovery-acceptance):
весь корпус повторно, с отдельным переходом STIF типа `c-snapshot` и
2 253 последующими сохранёнными наблюдениями, с остановкой до probe.
**Ограниченная аппаратная проверка LG short/stopped/reset-recovery завершена.**
Итоговое состояние LG: остановлен на ENDREADY016A/config26/RC16, fault0,
C/live IRCON80; прежний stopped FAULT историчен. Generic/EOC1/poll-fault и
более широкие проверки энтропии/RF/безопасности/сна остаются открыты;
hosted-CI pass не заявляется.
[Владение ADC/CSP, семантика общего регистра и оставшиеся аппаратные проверки](docs/VALIDATION.md#m2-deterministic-prng-coverage)
описаны отдельно. RF/noise seeding, ADC-преобразования, сон и криптографическая
случайность не реализованы; M2 #4 остаётся открытым.

## Ограниченный пассивный RX

Добавлен [ограниченный пассивный приёмник](docs/RADIO_RX.md):
каналы 11..26, один CRC-проверенный кадр, сырые RSSI/correlation и проверяемые
soft-stop/flush, без передачи, auto-ACK, DMA и включения IRQ.
`make test-radio-rx` подтверждает только **host/image/синтетическую симуляцию**.
Изолированный тестовый образ прошивать нельзя. Отдельный
`IMAGE=radio_rx_fixture` для обеих плат вызывает настоящие startup/board,
переключатель тактирования и RX-драйвер. Канал15, максимум16 ограниченных
попыток, остановки READY и терминальные END/FAULT. В отличие от девяти
прежних non-RF образов, эта прошивка **может включить радиоприём**.
Heartbeat увеличивается только после успешной публикации; BAD_CRC не
публикует кадр. При отказе RX может остаться активным даже с остановленным CPU;
нужен отдельно разрешённый полный сброс, а не resume/retry.
[Зафиксированный родительским процессом отказ и проба LG](docs/DEBUGGING.md#2026-09-18-lg-rx-fscal1-failure-and-probe)
выявили ошибку проверки резервных битов FSCAL1. Исправленный образ прошёл
[ограниченную аппаратную приёмку LG 2026-09-18](docs/DEBUGGING.md#2026-09-18-lg-bounded-passive-rx-acceptance):
первый приём, удержание ошибки таймаута до включения RF, затем отдельный
сброс и серия из16 попыток. Все14 опубликованных тел кадров совпали с
одновременным захватом Nordic; две попытки BAD_CRC ничего не опубликовали.
Предел16 попыток завершился устойчивым END с выключенным RX и пустыми FIFO.

[Демонстрация 2026-09-21](docs/DEBUGGING.md#2026-09-21-lg-tx-and-passive-rx-demonstration)
проверила текущий LG-образ размером9183 байта: одно10-байтное тело с CRC_OK
совпало ровно с одной записью одновременного захвата Nordic. Образ оставлен
в READY016A, RX выключен, FIFO пусты. Это пассивный приём окружающего трафика,
не ответ на отдельную передачу на канале26.

```sh
make BOARD=generic IMAGE=radio_rx_fixture test-radio-rx-fixture
make BOARD=lg_esl29_rev03 IMAGE=radio_rx_fixture test-radio-rx-fixture
```

Симуляторы запускать последовательно. Хеши,96-байтовый ABI состояния,
128-байтовый буфер, отдельный бюджет памяти и ограничения описаны в
[RADIO_RX.md](docs/RADIO_RX.md#bounded-passive-rx-board-fixture).
[Ручной runner](docs/DEBUGGING.md#parent-only-passive-rx-acceptance) требует
отдельного разрешения, проверки физического CODE и нового приватного файла
вне репозитория. Сырые кадры/идентификаторы не выводятся в stdout/CI.
Generic, калибровка метаданных, независимая проверка эфирного FCS и более
широкое восстановление после RF-отказов аппаратно не подтверждены.
Непрерывный приём без потерь и поддержка MAC/security/сети не заявляются.

Отдельные [ограниченные радио-очереди](docs/RADIO_QUEUE.md) содержат два RX-слота,
один TX-кандидат и четыре ISR-safe запроса. Foreground обрабатывает не больше
одного запроса через настоящий passive RX; заполнение не перезаписывает
занятые буферы. TX dequeue только копирует данные, а не передаёт их в эфир.
`make test-radio-queue` проверяет host, точный образ, IRAM alias и настоящие
прерывания модели C52 — **не RF/IRQ на CC2530**. В образы плат модуль
не включён; отдельный тестовый executable прошивать нельзя.

## Изолированные примитивы TX и CCA

[Ограниченный init-time TX/CCA](docs/RADIO_TX.md) реализует прямой TX,
условный TX по решению CCA контроллера и отдельное измерение CCA. Используются
настоящие FIFO/timebase, каналы 11..26 и явно заданный raw power `05`.
Завершение PHY требует нового TXDONE и подтверждённого покоя, а не ACK.
Занятый канал допускает следующий явный вызов только после проверенного
останова; ошибки фиксируются без скрытой очистки или повтора.

`make test-radio-tx` даёт **host/image/симуляционные**, не аппаратные результаты.
Отдельный тестовый executable прошивать нельзя.
[Образ платы с заблокированным при старте TX](docs/RADIO_TX_FIXTURE.md),
выбираемый через `IMAGE=radio_tx_fixture`, связывает настоящие clock/FIFO/TX.
Перед одной условной попыткой на канале26/raw power05 нужны отдельные ARM/RUN
и проверяемая остановка ADMITTED. Передаются только публичные байты `TXF1`,
без запроса ACK и реального идентификатора. Ошибки удерживаются без скрытой
очистки/повтора. `make ... IMAGE=radio_tx_fixture test-board` работает офлайн;
ручной RF runner не запускается сборкой или CI.

В отдельно разрешённом [аппаратном прогоне LG](docs/DEBUGGING.md#2026-09-19-lg-single-attempt-tx-acceptance)
одна попытка на прежнем образе **канала15** завершилась PHY_DONE; независимый
nRF52840 захватил ровно одно побайтно совпадающее публичное тело кадра.
Тот образ был оставлен остановленным в END. Позднее отдельно разрешённый
[прогон канала26](docs/DEBUGGING.md#2026-09-19-lg-channel26-isolated-tx-acceptance)
также дал одну PHY_DONE; в завершённом захвате с запросом90 секунд была ровно
одна запись с публичным телом кадра. Тот прогон оставил образ канала26 в END,
сниффер в sleep на26; координатор не менялся. Это не доказывает
постоянную исключительность канала, независимую FCS или калиброванные
мощность/тайминг.

[Демонстрация 2026-09-21](docs/DEBUGGING.md#2026-09-21-lg-tx-and-passive-rx-demonstration)
повторила одну независимо принятую передачу на канале26, затем отдельный
пассивный RX-образ принял совпадающий с захватом Nordic кадр на канале15.
Сейчас установлен RX, не TX. Это два отдельных опыта, не двусторонняя работа
без сброса и не управляемый обмен «запрос-ответ».

Для этого постоянная DATA сервиса clock уменьшена с45 до12 байт ценой десяти
дополнительных байт XDATA, без увеличения лимитов. Образы generic/LG занимают
11 291/11 331 байт CODE,347 байт обычной XDATA +64 зарезервированных;
SP на MMIO-остановках симулятора —`0x74`, максимум всего прогона —`0x77`.
Это измерения отдельных образов и выполненных сценариев, не полного
стека. Совместное использование с legacy RX без reset, интеграция очередей,
аппаратные ACK/retry, busy-channel/fault recovery и более широкая эфирная
приёмка ещё не подтверждены.
Прежние аппаратные записи не переносятся на новую сборку автоматически;
поддержка MAC/сети и калиброванная мощность не заявляются.

## Изолированный приёмник с AUTOACK

[Сервис RX/AUTOACK](docs/RADIO_AUTOACK.md) задаёт и проверяет PAN/short/IEEE
адреса, аппаратную фильтрацию version 0, CRC-метаданные и unslotted ACK с
Pending0. Он сохраняет запрос RX, копирует целые кадры из FIFO через RFD
и явно останавливает приём с последующим чтением оставшихся кадров, не
обрывая текущий RX/ACK. Тела с неверной CRC явно помечаются; ошибки сохраняют
владение радио без скрытой очистки.

`make test-radio-autoack` проверен **на host, по образу и в симуляторе, не
аппаратно**. Для обеих плат:4410 байт CODE,427 байт обычной XDATA +64 резерва,
максимум SP всего прогона`0x33`. Проверка входит в `test-common` один раз
для каждой платы; в прошивки плат модуль не включён.
**`radio_autoack_test.ihx` прошивать нельзя.** AUTOACK передаёт RF, а не
только слушает; аппаратный тайминг и конечное число эфирных ACK не доказаны.
Broadcast-AR и совместимость с игнорируемыми полями ACK остаются ограничениями.
Остановка с чтением FIFO не означает завершение IFS, закрытие непрерывного
окна MAC/POLL, передачу владения обычному TX или проверку безопасности.

**Nordic также разрешено готовить как управляемый активный тестовый узел.**
Подготовка отдельно от разрешения заменить прошивку или передавать в эфир;
она не блокирует независимые части разработки CC2530.

[Лабораторный пробник для Nordic](tools/nrf_stimulus/README.md) — это
**собираемый из исходников офлайн-прототип**, пока не установленный на устройство:
после ARM/RUN допускается одна попытка передачи публичного кадра с запросом
ACK на канале26/номинальных-20dBm, затем ограниченный обычный приём.
Драйвер и SL собираются из исходников; диагностическая правка PHYEND не
подменяет полученный ACK фактом завершения TX. Это не образ CC2530 и не
установленная замена снифферу. Host-проверки, внешняя сборка и статический
анализ не доказывают RF/тайминг или восстановление устройства.
[Сверка файлов восстановления](docs/NRF_RECOVERY.md) также не заменяет новые
физические чтения и проверку восстановления перед перепрошивкой.
Отдельный [ручной сценарий чтения](docs/NRF_RECOVERY.md#explicit-read-only-acquisition-operator)
готовит два полных чтения flash/UICR через специально проверенный режим
программатора. По умолчанию он работает офлайн; обычные тесты не создают
резервную копию устройства и не доказывают восстановление.
[Отдельное ручное чтение](docs/NRF_RECOVERY.md#2026-09-20-corrected-runtime-manual-readback)
сохранило приватно два совпадающих чтения flash/UICR полной длины, но не
зафиксировало ACL. [Последующее ручное чтение v2](docs/NRF_RECOVERY.md#2026-09-20-acl-qualified-manual-readback)
совпало с этими данными и подтвердило три стабильных снимка ACL.
Атомарность и пригодность для восстановления остаются непроверенными;
это не доказывает восстановление прошивки и не разрешает установку помощника.
[Офлайн-планировщик](docs/NRF_RECOVERY.md#offline-page-overlay-report) проверяет
сохранение байтов вне образа и UICR по приватным файлам. Он выдаёт только
отчёт с хешами и счётчиками, не данные для записи и не разрешение на прошивку.
[Отдельный SRAM-вариант](tools/nrf_stimulus/README.md#optional-sram-only-profile)
прошёл host/image-проверки: 73 220 байт в RAM, без загрузочных байтов во flash.
Это основа варианта без замены прошивки, пока не загруженная на устройство.
[Примитивы передачи управления через MEM-AP](tools/nrf_stimulus/README.md#checked-volatile-handoff-preparation)
уже проверены на host, но оператора для запуска на устройстве и подтверждённого
возврата к работающему снифферу ещё нет. Остановка на исходном reset-векторе
не означает восстановление его работы.
[Отдельный read-only профиль v3](docs/NRF_RECOVERY.md#opt-in-v3-startup-source-binding)
собирает недостающие селекторы запуска и параметры CPU/watchdog/NVMC.
Условное совпадение с исходниками не разрешает запуск и не заменяет
проверку silicon/board/reset и восстановления сниффера.
[Отдельное чтение v3 с платы](docs/NRF_RECOVERY.md#2026-09-20-v3-startup-binding-manual-read)
уже дало стабильные снимки и полное побайтное совпадение flash/UICR
с сохранённым состоянием. SRAM-помощник пока не загружался и не запускался.

## Изолированная основа MAC Timer

[Сервис MAC Timer](docs/MAC_TIME.md) для бодрствующего чипа задаёт периоды
512/`FFFFFF`, подтверждает асинхронный запуск через STATE и согласованно читает
raw fine/coarse-счётчики с обходом erratum TI для младшего байта FF.
Независимые ограничения времени/работы и сохранение первой ошибки исключают
бесконечные повторы и частичную выдачу результата. `make test-mac-time`
проверен **на host, по образу и в симуляторе**. Нужны исключительное владение
таймером после reset и остановленное радио. Это не захват конца TX/ACK,
калиброванные символы или настоящий MAC-адаптер.
В образы плат модуль не включён; `mac_time_test.ihx` прошивать нельзя.

## Офлайн-состояния передачи MAC

[Ограниченный MAC-планировщик](docs/MAC_TX.md) реализует unslotted CSMA-CA,
проверку legacy ACK/DSN и повторы для одной копии незащищённого DATA-кадра
либо выбранных команд Beacon Request/Association Request/Data Request через настоящий
MAC-кодек. Association Request допускает capability `88`/`8C`: receiver-on ED,
запрос короткого адреса и правдивый признак питания от вызывающей стороны.
Его ACK подтверждает только получение команды, не ассоциацию или членство.
Data Request требует оба адреса и сжатый нешироковещательный PAN;
его ACK/Pending не реализует polling или получение ответа.
Передача запроса сама по себе не сканирует канал и не принимает Beacon.
Явно ограничены backoff, пять CCA на попытку, до четырёх попыток передачи,
время и число шагов; освобождение радиовладения
требует подтверждённого останова. Повторы сохраняют кадр и DSN; отсутствие
ACK не означает, что получатель ничего не принял.

`make test-mac-tx` даёт **host/image/симуляционные** результаты.
Время — абстрактные 32-битные символы, не raw Sleep Timer. Настоящего
радиоадаптера, приёма ACK после TX и аппаратной проверки таймингов пока нет;
существующие reset-exclusive TX/RX нельзя просто соединить. Измеренный запас IRAM
отдельного образа не подтверждает вместимость стека или вложенных IRQ.
Модуль не включён в образы плат; `mac_tx_test.ihx` прошивать нельзя.

Отдельный [сборщик Beacon-кандидатов](docs/NWK_CANDIDATES.md) хранит четыре
копии предварительных записей через настоящие MAC/NWK-декодеры. Нужны явные
метаданные канала/CRC, профиль PRO2, BO15, Association Permit и ED Capacity.
Корректное изменение обновляет или удаляет запись; повреждённый кадр и
переполненная таблица не затирают другие записи. `make test-nwk-candidates`
проверен **на host, по образу и в симуляторе**. Это не активное сканирование,
ранжирование родителей, проверка актуальности, ассоциация или членство в сети.
Отдельный executable исключён из прошивок плат и CI-артефактов.

[Ограниченный выбор родителя](docs/NWK_PARENT.md) теперь работает по неизменной
таблице: явно заданная сеть, переданные оценки стоимости связи и допустимости,
Update ID с учётом переполнения. Неоднозначные и циклические ID дают ошибку,
а не случайный выбор по порядку приёма; глубина для профиля2 не ранжируется.
`make test-nwk-parent` проверен **на host, по образу и в симуляторе**.
Это не процедура join и не источник калиброванной оценки связи.

[Офлайн-автомат активного сканирования](docs/MAC_SCAN.md) добавляет обход
каналов по возрастанию, настоящие состояния Beacon Request/DSN/CCA,
подтверждаемые окна приёма и сбор копий кандидатов. Отдельно сохраняются
маски переданных запросов/недосканированных каналов и признак переполнения.
Освобождение требует подтверждённого восстановления PAN/канала/фильтра/RX.
`make test-mac-scan` проверен **на host, по образу и в симуляторе**,
но это не работающий сканер на плате. У тестового образа из шести модулей
остаётся 3201 байт до лимита CODE 32 КиБ; вместимость полного стека
не подтверждена. Радиоадаптер, аппаратные timestamps (#40), полный выбор
родителя и ассоциация ещё не реализованы; `mac_scan_test.ihx` прошивать нельзя.

[Контекст Association Response](docs/MAC_ASSOCIATION.md) добавляет ограниченную
одноразовую выдачу метаданных через настоящий кодек. Проверяются выбранные
PAN/канал/локальный IEEE и известный IEEE координатора; адрес, полученный после
выбора по короткому адресу, явно остаётся **без подтверждённой привязки**.
Явный профиль приёма R22 дополнительно распознаёт несжатые ответы и разрешает
широковещательный PAN назначения только при наличии выбранного PAN источника
в самом кадре. Поведение по умолчанию и прежний путь POLL не расширены.
`make test-mac-association` проверен **на host, по образу и в симуляторе**:
15 086 байт CODE и696 байт обычной XDATA +64 зарезервированных в отдельном
тестовом образе. Это измеренные размеры теста, не расход памяти всей прошивки
и не доказательство вместимости полного стека. Контекст не отправляет запросы
извлечения ответа, не передаёт обязательный ACK, не восстанавливает радио
и не завершает ассоциацию. `mac_association_test.ihx` прошивать нельзя.

Отдельный [контроллер извлечения ответа через Data Request](docs/MAC_POLL.md)
использует тот же передатчик для одной условной операции POLL. Он учитывает
Pending0/1 и окно от аппаратно зафиксированного конца принятого ACK, используя
заданное вызывающим кодом действующее значение PIB, без выдуманного тайм-аута.
DATA и команды копируются; команды требуют отдельной доставки вызывающим кодом.
В тестовой композиции Association Response передаётся настоящему контексту
ответа независимо от результата POLL и его дедлайна.
`make test-mac-poll` проверен **на host, по образу и в симуляторе**:
56 общих сценариев, включая все52 прежних. Явный профиль приёма R22 теперь
передаёт поддержанные несжатые ответы дальше, не расширяя фильтрацию DATA
или поведение по умолчанию. Непрерывный RX, немедленный ответный ACK, IFS и закрытие окна
без потерь пока остаются обязанностями будущего радиоадаптера.
Это не циклический опрос, полная ассоциация или членство в сети.
`mac_poll_test.ihx` прошивать нельзя.

## Изолированное чтение зарезервированной flash

[Первый срез flash](docs/ARCHITECTURE.md#reserved-flash-read-foundation)
читает 1..32 байта из зарезервированных страниц125/126 с проверкой чипа,
контроллера, отображения банка и границ буфера. Исходный банк восстанавливается
до выдачи данных; при ошибке буфер не изменяется, ошибка сохраняется.
Страница lock/config и отдельная information page исключены.
Есть **host-, image- и simulator-проверки**, но нет аппаратного подтверждения.
Этот модуль остаётся только читателем. `make test-flash` работает офлайн;
отдельный `flash_test.ihx` нельзя прошивать в плату.

Отдельный [внутренний исполнитель команд из RAM](docs/ARCHITECTURE.md#internal-ram-flash-command-executor)
проверен на host, по точному образу и в alias-aware симуляторе
(`make test-flash-exec`). Выполняется настоящий скопированный код: возврат
возможен только после остановки контроллера, иначе сохраняется RAM-only
fail-stop. Idle контроллера сам по себе не подтверждает содержимое flash.
Отдельный `flash_exec_test.ihx` нельзя прошивать в плату.

Добавлен [публичный сервис стирания и записи](docs/ARCHITECTURE.md#verified-reserved-page-erase-and-program):
настоящие команды выполняются этим RAM-исполнителем, результат проверяется
через существующий читатель. После reset история неизвестна даже при allFF:
запись разрешается только после нового проверенного стирания и лишь одной
попыткой на слово. `make test-flash-write` подтверждает это на host,
по точному образу и в симуляторе, **не аппаратно**. Аппаратная приёмка
и сохранение security counters пока отсутствуют; отдельный общий NV-журнал
ниже имеет только offline-подтверждение. `flash_write_test.ihx` нельзя
прошивать в плату.

[Двухстраничный snapshot-журнал](docs/NV_RECORDS.md) хранит одну непрозрачную
запись 1..128 байт: версия, generation без переполнения, CRC всей страницы
и отдельное слово commit, записываемое последним. Настоящий flash backend
стирает только неактивную страницу; возврат к старой записи при повреждении
явно отмечается и требует разрешения перед заменой. `make test-nv-record`
даёт **host/image/симуляционные** результаты с прерыванием команд и reset,
но не аппаратную гарантию сохранности. Учёт erase ограничен текущим запуском,
а не сроком службы flash. Security counters, ключи и членство в сети не
реализованы; модуль в образы плат не включён.

### Flash fixture с блокировкой при старте — только офлайн

Отдельный `IMAGE=flash_fixture` использует настоящие сервисы выше, **без RF**.
После старта команды запрещены: нужны два разных пакета ARM/RUN в RAM,
каждый в пределах256 опросов, с выбором одной зарезервированной страницы.
Успех означает одно стирание и две проверенные записи слов, проверки
UNKNOWN/USED и терминальный END/FAULT. Обычный boot/resume/reset не запускает
стирание. Автоматического аппаратного runner и повторов после ошибки нет.

```sh
make BOARD=generic IMAGE=flash_fixture test-flash-fixture
make BOARD=lg_esl29_rev03 IMAGE=flash_fixture test-flash-fixture
```

Оба варианта проверены **только на host, по образу и в симуляторе**:
4168/4208 байт CODE,500 байт XDATA с резервом, прежний лимит512 байт.
[Процедура scratch/recovery, ABI и ограничения отладчика](docs/FLASH_FIXTURE.md)
описаны отдельно. Аппаратный запуск заблокирован до нового явного разрешения
для конкретной платы, scratch-страницы, резервных копий и разрушительных
операций, с независимой полной проверкой исключённых областей.
Устройства, приватные копии и идентификаторы не читались; #8 остаётся открытой.

## Подход

Независимо от аппаратной проверки добавлен [ограниченный MAC-кодек](docs/MAC.md):
DATA/ACK и форматы команд association request/response, disassociation,
data request и beacon request, а также Beacon version 0 без GTS-дескрипторов,
со списками pending-адресов и непрозрачной нагрузкой верхнего уровня.
Это только байтовый формат без PHY/FCS, не поиск сети. Кодек проверяется на компьютере
и в отдельном SDCC-образе под симулятором, но не включён в прошивки плат.
Отдельный [декодер NWK Beacon R22](docs/NWK.md) разбирает 15 байт Zigbee-метаданных
внутри этой нагрузки, но не принимает решения о совместимости профиля,
выборе сети или родителя.
Независимый [кодек NWK Data](docs/NWK.md#nwk-data-frame-codec) разбирает и
собирает ограниченные незащищённые unicast/broadcast-кадры с дополнительными
IEEE-адресами. Security и расширенные варианты маршрутизации явно отклоняются;
это офлайн-формат, не разрешение передавать незащищённый Zigbee-трафик.
Отдельный [кодек APS Data](docs/APS.md) добавляет normal-unicast заголовок,
endpoints, profile/cluster ID и непрозрачную нагрузку. Цепочка MAC/NWK/APS
проверяется на компьютере и в отдельном SDCC-образе с контролем памяти.
APS security, broadcast/group delivery и расширенные заголовки явно отклоняются;
бит ACK request не означает реализацию транзакций или подтверждений.
Добавлены [wire-кодеки ZCL Revision 8](docs/ZCL.md): обычный/manufacturer-specific
заголовок и 38 типов значений в байтовом представлении, включая 8..64-битные
значения и короткие строки. Отдельные read-only модель атрибутов и диспетчер
обрабатывают Read/Discover, ошибки команд и исключения без ответа.
Полная цепочка Discover-then-Read через MAC/NWK/APS/ZCL проверяется на
компьютере и в отдельном SDCC-образе.
[Read-only модель Basic](docs/ZCL_LAB.md) теперь предоставляет шесть атрибутов
через эти же обработчики, с копированием строк и явно синтетическими
лабораторными значениями. Есть host/image/simulator-проверки для обеих плат,
но нет зарегистрированного endpoint: выбор profile/device, запись, Identify,
измерения и reporting остаются открытыми. Прошивки плат эти модули не вызывают.
Errata остаётся риском conformance, а не запретом на работу по базовому тексту.
Эти кодеки не реализуют передачу RF, работающий MAC, ассоциацию или Zigbee join.

Радиодрайвер можно адаптировать из открытого кода Contiki для CC2530/SDCC,
не перенося всю ОС. Теперь выполнена [отдельная сборка и оценка закреплённой
версии](docs/PROVENANCE.md#contiki-cc2530-reference-evaluation): upstream-пример
линкуется после двух правок совместимости с SDCC, но в образе остаются ошибки
инициализации и определения текущего приёма. Это не работающий порт и не
доказательство непригодности Contiki; код в проект не импортирован.
MAC, NWK, APS, безопасность, ZDO и ZCL остаются отдельными этапами.
Объектные библиотеки, собранные IAR, не считаются совместимыми с SDCC.

Маршрутизация, обслуживание дочерних устройств и функции Trust Center нам
не нужны. Но join/rejoin, необходимые ответы ZDO, polling для SED, ключи,
защита от повторов и надёжное сохранение счётчиков остаются обязательной
частью задачи. Сначала проверяется корректность обычного ED, затем сон.

Ориентир — **Zigbee Core R22 + PRO BDB 3.0.1**, документ `16-02828-012`
от 28 сентября 2021 года, а не BDB 1.0 или PRO 2023/BDB 3.1.
Первый ED для централизованной сети — лишь подмножество BDB: поддержка
распределённых сетей отложена. [Проверка errata и реализация требований](docs/CONFORMANCE.md)
остаются открытыми; сертификация и готовая совместимость с координаторами
сейчас не заявляются.
